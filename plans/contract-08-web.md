## What each item changes

Rules that apply to every item (not repeated): additive only; every operation keeps `x-required-role`, `operationId`, `summary`, a `default` problem response and `application/problem+json` for every 4xx; every new non-GET carries `CsrfToken`, `IdempotencyKey` and a documented 403; lists use `Cursor` and `Limit` (maximum 500) and `next`; arrays carry `maxItems` and strings `maxLength` or a `pattern` (S11); a response field added to an existing schema is optional and the schema keeps `additionalProperties: false` (so the old mocks stay valid); every new schema is referenced in the same commit (the `no-unused-components` gate); `GET`s send `Cache-Control: no-store` unless they are `content` operations; new tags carry a description (`tag-description`); every new domain field is `Option` or defaulted with `#[serde(default, skip_serializing_if = ...)]`, as `Draft.severity` was (`crates/domain/src/write.rs:336`).

The unit is the flagged value, or its whole line where the producer works by lines (06's views do, `flagged_lines`); the MCP layer already replaces per value (`hub-mcp/src/output/redact.rs:7`); the marker is the same.
2. **`masks`.** New `Mask {line, column (1-based, characters, of the masked text), length (characters of the marker), hidden (characters hidden), rule: ShortText, setting: SettingPath or null}` and an optional `masks: Mask[]` (at most 1,000) on `FileContent`, `ServedFile` and `DocText` only. It holds no value (`Mask` has no `text` or `value`). `setting` is what `revealValue` needs; null for plain text. Elsewhere (`SettingValue`, `DiffLine`) the marker pattern `^\[REDACTED: [0-9]+ chars, [a-z_]+\]$` is documented and is the recognition (a user-authored marker makes the client show a Reveal that answers 404, which is harmless).
3. **Reveal.** Unchanged: `revealValue` by `setting` (Editor, audited by 06, 30 a minute). A secret in a plain text file cannot be revealed in the web (06 returns 404 for it today, `docs/threat-model.md:543`); a reveal by line is an optional second operation, not proposed.
4. **Edit round trip.** Edit mode is off while `masks` is non-empty (the client rule). Defence in depth: a write whose content contains the marker pattern is refused 422 `invalid_content` with a new `ValidationIssue.kind` `redaction_marker` (a value added to `domain::IssueKind`, `crates/domain/src/write.rs`, pinned by `rejection_detail_is_optional_and_matches_the_domain`; a grep of `IssueKind::` finds only constructions in `hub-writes` and no exhaustive match). 06 implements the check.
5. **Cache.** The ETag of a masked response includes the scan configuration's version, so a changed configuration is not served from a stale 304.
6. **Performance.** The scan runs per content hash and is cached by `(hash, scan configuration)` (moka, weighted); `P7.file_content_cold` (80 ms) and `P7.compare` (100 ms) are measured with masking on. The engine has no registered scan benchmark today (`grep` of `crates/engine/benches`; `perf/budgets.toml` has no scan row).

- **Domain, ports, migration.** `IssueKind::RedactionMarker` only. No migration, no new port. **Tests (new).** `every_text_bearing_schema_states_how_it_is_masked` (a table of the schemas above, each `masked` or `raw by design: reason`, failing when a schema with a `text`, `diff`, `snippet` or `hunks` property is not in it), `mask_has_no_value_field`, `redaction_marker_is_an_issue_kind_of_the_domain_and_the_document`. **Owner later.** 05: the edge, the cache, a planted-key test over every read operation (the matrix `hub-mcp` already has), a benchmark; 06: marker refusal, and `Proposal`/`Draft` already comply; 14: docs text.
- **Options (Q1).** M0: nothing here, the web shows what it gets, and the human records a relaxation of S14b for web reads in `docs/decisions.md` (only a human can). M3: a file with flagged values is "content withheld" in the web, like a denied file (no masks, no editing, no diff; six files flagged today, Q20). M1 is the default because it keeps S14b whole at the cost of one scan per content hash.

## Risks

- **Masking against the read budgets (security and P7).** CG7 adds a scan to the cold path of file content (80 ms) and compare (100 ms), and the engine has no registered scan benchmark. Contained by the cache key `(content hash, scan configuration)`, the benchmark 05 must register, and escalation with p50, p95, p99 rather than a loosened threshold.
- **Declared but unmounted operations.** Eight new operations have no server (`previewPr`, the two offers, `getProposal`, `getDraft`, `getGithubCredential`, `listGitRefs`, `renderDoc`); only the six `writes` ones are pinned (F3). A forgotten one is a 404 against a generated client that MSW hides. Contained by the `LATER` rows, the owner table, the PR text and the human's decision in Q11.
- **Literal churn in merged crates and in-flight branches.** 27 literals in five crates (one in the fact engine), and the 05 and 14 branches (not in this clone) build the same structs, so they break until they merge `main`. Contained by optional fields with serde defaults, the mechanical nature of the edits, and the owner notes.
- **The HTML sink (S12).** A sanitiser bug in CG11 is stored XSS behind the CSP's last line (Trusted Types policy `lanekeeper-docs`). Contained by a stated allowlist, rendering after the scan, a conformance corpus here and the owner's XSS corpus, and the CSP; it is the reason the item needs a human.
- **New Viewer exposures.** `UserRef` names (Q6), Git ref names, restart offers (Operator only), and, if CG9 is taken, actor ids and actions. Contained by roles on every operation, no email, no `diff` in any activity row.
- **Control of a branch the guard does not watch.** Contained by Check 1, the per-commit file lists, the never-touched grep and the review; an agent that edits `db/migrations` or `perf/budgets.toml` fails the grep.
- **Compatibility.** `additionalProperties: false` on response schemas means a server that adds an undeclared field is wrong; every addition here is optional and declared. The additive check, the conventions tests and redocly run per commit. The orval treatment of a `text/event-stream` media type with an object schema is untested here (08 T1 may need an override).
- **Verification limits.** Docker-backed, `cargo deny`, `cargo audit`, fuzz and `just` itself cannot run here; no migration and no dependency means none of them is affected, but CI is the proof.
