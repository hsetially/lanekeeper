**What "prompts" means here.** `prompts/` holds work orders for the coding agents that build Lanekeeper. They are not runtime LLM prompts: there is no server-side LLM (D51), and the product's only AI surface is Cursor calling the hub's MCP server (`docs/mcp-tools.md`, `skills/lanekeeper/SKILL.md`). The brief's item 3 ("structured outputs expected by `/api` match the schema instructions in `/prompts`") is therefore assessed on two surfaces:

1. the work-order prompts and the reviewer's verdict format, which the orchestrator machine-reads;
2. the MCP tool output contract and the Cursor skill, which steer the model at runtime.

---

## 1. Executive summary

**Verdict.** The contracts that exist are unusually rigorous, but as specified the system cannot reach its pilot. Four pilot-critical gaps have no owner, and one security layer (CSRF) is built but never applied.

### What is strong

- **REST contract.** Every one of the 91 operations declares `x-required-role`. Every non-GET carries `X-CSRF-Token`, except the HMAC-verified webhook. Every write carries `Idempotency-Key`. Every JSON request body except the webhook's is closed (`additionalProperties: false`), and every array has `maxItems`.
- **Enum alignment.** Enums agree across `docs/`, `api/openapi.yaml` and `crates/domain`, with two exceptions: `Confidence` and the audit `via` field.
- **MCP contract.** All 27 tools match between `docs/mcp-tools.md` and the code, and a test locks that. Tool roles equal the REST `x-required-role`. Redaction and the 16 KB cap are enforced centrally. No untrusted text reaches a tool description, summary or elicitation message unlabelled. **No path where a secret leaks was found.**
- **Records.** Decisions and residual risks are written down precisely, per component.

### What blocks the pilot (Critical)

1. **C-1. No prompt owns composing the hub, and S3 (CSRF) is enforced on no composed route.**
   - `crates/hub/src/main.rs` refuses to start.
   - The guard that registry, writes and MCP mount through (hub-platform's `GuardedRouter`) has no CSRF step.
   - The hub's own test asserts that an editor's POST with no token or `Origin` returns 200.
2. **C-2. The D2 edit lock can never be lifted through the API.** `swimlanes.editing_unlocked` is written only by `adoption/confirm.rs`, which has no route. So every edit, upload, delete, revert and approval, over REST and MCP alike, returns 423 indefinitely.
3. **C-3. Nothing can create a swimlane, register an agent or register a sentinel.** 33 of 91 operations (`/api/v1/admin/*`) have no implementer and no owning prompt. Agent join (S5), sentinel `hello` (D123) and milestone M1 all depend on them.
4. **C-4. S14b ("the web UI masks flagged values by default") has no owner and no contract support** for raw file text, diff hunks and search lines (D111).

### Systemic themes behind the High findings

- **Decision debt.**
  - D89–D124 (36 decisions, about 81% of the words in `decisions.md`) were written after the prompts, and no prompt cites anything above D88.
  - Stale task text therefore still tells agents to do things that later decisions forbid. One example is `ignore::WalkParallel`, which follows symlinks during the walk and so breaks S17.
  - 23 decisions are marked "to be confirmed at review", and `prompts/REVIEW.md` has no step that confirms them.
- **Hand-offs that never landed.** About 30 obligations that merged plans and decisions assign to prompts 08, 09, 15, 16 and 17 are missing from those prompts (§4).
- **Contract defects that standard tooling will hit.**
  - Six `allOf` schemas can never be satisfied under JSON Schema 2020-12, including `GET /me`. The repo's own test walker deliberately merges `allOf`, which hides this.
  - There is no 429, 503, 504 or `Retry-After` anywhere in the contract.
  - The hash-conflict 409 is reused for conflicts that have no hash.
  - The SSE stream is untyped.
- **Guardrail gaps on the AI surface.**
  - The Cursor skill says to read the file (MCP output masks flagged values as `[REDACTED: …]` markers) and then "write the complete new content". Nothing on the server refuses a marker in written content, so a confirmed edit can overwrite a real value with the marker.
  - The draft-mode fallbacks tell the user to "confirm in the web UI" for actions that recorded nothing.
  - The Cursor compatibility test (D91 T0) is entirely NOT RUN, and no prompt's acceptance enforces its `--strict` gate.

### Scorecard

|---|---|---|
| docs ↔ api: endpoints, schemas, auth, status codes | **Partial** | Enums are aligned except two. Four v1 capabilities have no operation: adoption, intentional divergence, creating a swimlane, reading a draft. The auth and session flow is under-documented. Required status codes are missing. |

| API robustness | **Partial** | Input bounds are excellent. The error, status-code and composite-schema layer is defective. Edge controls (CSRF, B16 problem types, catch-panic) are missing or not composed. |

**Totals:** 4 Critical, 23 High, 25 Medium, and a Low/hygiene batch.

## 6. Appendix: how the `allOf` defect was reproduced

```python
# python3 -I allof_check.py api/openapi.yaml   (jsonschema 4.26, referencing; Draft 2020-12)
import sys, yaml
from jsonschema import Draft202012Validator
from referencing import Registry, Resource
from referencing.jsonschema import DRAFT202012
spec = yaml.safe_load(open(sys.argv[1]))
reg = Registry().with_resource("urn:spec", Resource.from_contents(spec, default_specification=DRAFT202012))
def check(name, inst):
    errs = list(Draft202012Validator({"$ref": f"urn:spec#/components/schemas/{name}"}, registry=reg).iter_errors(inst))
    return "VALID" if not errs else "INVALID: " + errs[0].message
print(check("ConflictProblem", {"type": "about:blank", "title": "Conflict", "status": 409, "current": "a" * 64}))
# -> INVALID: Additional properties are not allowed ('status', 'title', 'type' were unexpected)
```
