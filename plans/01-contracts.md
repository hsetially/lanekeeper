## Tests, benchmarks and fuzz targets

- **Unit and property (proptest):** domain validators and mapping (T2); ports fakes, including `tokio::time::pause` tests for the gateway timeout, lease expiry and event-bus lag (T3); proto round trips (T4); bench-check arithmetic (T8).
- **Golden/snapshot (insta):** `DomainEvent` and enum wire names (stable serde names are part of the contract); fixture `manifest.json` at `--scale small`.
- **Integration against real Postgres 16 (testcontainers, pinned `pgvector/pgvector:pg16` digest):** migration, grants, triggers, partitions, outbox NOTIFY (T6). With `LK_REQUIRE_DOCKER=1` (set by `verify-01` and CI) a missing Docker daemon fails the tests; without it they print a skip line, so a plain `cargo test` works on machines without Docker. This must be agreed (Q7).
- **Contract linters:** `buf lint` and `buf breaking` against `main` once a baseline exists; `redocly lint` with assertions.
- **Fuzz:** three targets, seeds, 30 s smoke (T9). The targets assert invariants, not just no-panic: accepted `NfsPath` has no `..` component, no NUL, <= 1,024 bytes and re-parses to itself; `CompareRef` displays and re-parses to itself; mapping reverse never panics and `forward(reverse(p)) == p` when it succeeds.
- **Benchmarks:** none authored by this prompt (it owns the registry, not the benches). `bench-check` itself is tested; its performance matters only in that it must stream `sample.json` files without loading the whole `target/criterion` tree into memory.
- **Docs lint:** `mcp_tools_doc.rs` for T7.

## Risks

Largest security risks:

1. **Migration grants (S9, S21).** A wrong grant silently voids the append-only audit log. Mitigations: explicit grants, the `every_table_has_a_grant_decision` test, trigger independent of grants, `UNIQUE(prev_hash)`, definer function reviewed (Q18). Roles are never created by the app-owned path.
2. **Validators are the only gate for paths (S11).** `NfsPath`, `PathMappingRule`, `CompareRef` are fuzzed and proptested; all ports take typed values, not `String`, so a hole here is a hole everywhere. Backslash/Unicode choices are in Q13 for a human.
3. **Secret type (S21).** If `Secret<T>` gains `Serialize` or `Debug` leakage, every later prompt inherits it. Compile-time assertion test; error enums carry no input text.
4. **Supply chain (S19).** Many new dependencies land at once (tonic/prost/protox, sqlx, testcontainers, proptest, insta, toml, tokio, a YAML crate, libfuzzer-sys). Each must be >= 14 days old and clear `cargo deny` and `cargo audit`; sqlx's default features can pull the `rsa` advisory through the MySQL driver, so `default-features = false` with only `postgres`, `migrate`, `runtime-tokio`, `tls-rustls-aws-lc-rs`; no `openssl`. Each is justified in the PR.
5. **Contract mistakes are expensive.** Appendices A to C and the Q-table items marked "Yes" are the human review points before T4 to T8 start; proto fields are numbered once and never reused.

Largest performance risks:

1. **Registry honesty (P1-P15).** An unmeasurable or loosened budget makes later gates meaningless. Thresholds are copied from `docs/performance.md` and tested against it (`thresholds_match_docs_performance_md`); p95 comes from criterion's per-sample data, not the mean.
2. **Schema shape for the P7/P12 reads.** Missing indexes in `0001_init.sql` would only show up in prompt 05/16. I include the keyset and trigram indexes the budgets imply (`settings_index` GIN on `setting_path`, `git_tree_index` PK, `file_observations (swimlane, path, observed_at DESC)`), and flag that EXPLAIN checks (P12) belong to 05.
3. **Fixture generation time and size at target scale** (80,000 files, 60 branches). The generator streams files and uses `git fast-import`; the target-scale determinism check is `--ignored` and only run in `verify-01`, not in `cargo test`.
4. **Fakes drive wave-1 behaviour.** An unrealistic fake (unbounded buffers, no timeouts) teaches other agents bad habits, so every fake is bounded and the conformance suites test the bounds.

Environment risks for the implementer: this sandbox lacks `just`, `cargo-deny`, `cargo-audit`, `buf`, `redocly`, `cargo-fuzz`, a nightly toolchain and a Docker daemon. The implementer must install the Rust tools via `cargo install --locked` at pinned versions (network via the proxy), `buf`/`redocly` via the root pnpm lockfile, and needs a Docker-capable host for T6; if Docker is not available the T6 Verify cannot be proven in this environment and must be run in CI or on a developer machine before merge. Say so in the evidence file rather than skipping silently.
