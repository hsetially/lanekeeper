## Design notes

Choices that shape the tests. Anything that needs a human is also in the ambiguity table.

**Shape.** The engine takes typed inputs only (`NfsPath`, `LogicalFile`, `TenantId`, `TenantSet`, `ChannelName`, `AppName`, `ContentHash`, `Bytes`) and returns plain structs that 05 maps to `Finding`, `Comparison` and the other DTOs. There is no clock, no I/O, no tokio, no `HashMap` and no global state: functions take `now: Timestamp` where a time matters, and a `CancelFlag` (an `AtomicBool`) where a caller needs to stop long work, because a wall-clock timeout would make output depend on machine load. All bounds are on sizes. Caches (moka), pagination cursors and database writes belong to 05; the engine returns whole, sorted, capped result sets.

**Limits** (`Limits`, one struct, every default overridable and tested at its boundary): input 2 MiB (the agent and upload ceiling), nesting depth 64, nodes after alias expansion 500,000 (this is the alias-bomb defence: expansion is counted as nodes, never materialised past the budget), settings per file 200,000, scalar 64 KiB, setting path 1,024 bytes (= `SettingPath`), warnings per file 1,000, diff lines per side 50,000, inline-diff line 4 KiB, regex pattern 512 bytes (= `TextQuery::MAX_PATTERN_BYTES`), regex `size_limit` 1 MiB, `dfa_size_limit` 8 MiB, `nest_limit` 50, hits 500 total and 20 per file (= the `TextQuery` defaults), findings locations 50 per finding. Exceeding one returns an error value that names the limit and never the input.

**Parsers.** YAML: an event-level parser (marks for line and column, anchors and aliases as events, so alias expansion is counted without building the expanded tree). Candidates and the decision procedure are in A7. Merge keys (`<<`) are expanded the way SnakeYAML does (explicit keys win), because the services run Spring Boot (A8). JSON: strict syntax with positions (A7). `.properties`: a small own parser (`=`, `:` or whitespace separators because the config-server's own fixture uses `LOG_LEVEL: INFO`; `#` and `!` comments; continuation lines; `\uXXXX` escapes; duplicate keys are warnings; last wins), fuzzed. A parse warning never blocks; a parse error or a limit does (D45).

**Flatten.** Rules from `docs/domain-model.md`: `a.b.c`, `a.b[0]`, `a["x.y"]` for keys containing `.`, `[` or `]` (and `"` and `\` escaped inside the quotes), `#<doc>/` prefix for multi-document YAML, JSON the same as YAML, `.properties` keys as they are. Scalars keep the decoded text (quotes removed; `yes` stays `yes`) and a `ValueType` from the YAML 1.2 core schema (quoted = string; `yes/no/on/off` stay strings and get `ValueFlag::YamlBooleanLike`). `${...}` is kept literally. A key encoder and decoder pair is a property-tested inverse.

**Index and locations.** `index_settings` runs the Rust parser first, enforces every limit, and only then gives the same bytes to tree-sitter, so the C parser never sees input the Rust side rejected; tree-sitter runs with a progress callback that cancels on a node budget. Its line range for each setting path is checked against the parser's mark for that path; a disagreement is a test failure on the fixtures and a `LocationMismatch` warning (location dropped) at run time, never a panic. The same function feeds P6, so it is the hot path.

**Effective config.** `whole_file`: the tenant file replaces the base file; `spring_merge`: maps merge key by key, scalars and lists are replaced as a unit (a higher source that defines any `a[n]` drops every lower `a[*]`, which is the Spring Boot binder rule), a scalar against a map is replaced by the higher source; optional root `application.*` is the lowest layer. Every value carries its `Origin` (file, rank, location). T10 replaces how the mode is chosen: `Resource` means whole file and `PropertySource` means merge, so `MergeRules` and its tests go in the same commit (D82 supersedes D14).

**Hashes (pinned by insta goldens, because 05 may need to reproduce them).** Effective hash of a logical file in a swimlane = SHA-256 over the chosen whole file's content hash (line endings normalised for structured and text) and, for each placeholder the file contains, the key and its resolved value or an "unresolved" marker, sorted by key. Two files render identically exactly when this hash matches, and no rendering is needed to compute it. With several tenants (Q34) the swimlane value is the common hash when every tenant agrees, otherwise a hash over the sorted (tenant, hash) pairs. Directory hash = SHA-256 over entries sorted by raw name bytes: `u32_le(name length) || name || kind byte || 32-byte child hash`.

**Diff.** `similar` with `Algorithm::Patience` (similar has no histogram variant). Line endings are normalised first; if only they differ, no hunks and `eol_only = true`. Hunks carry 3 lines of context and are built in one pass. Above `Limits::diff_lines` the function returns a single "too large to diff" outcome, deterministically. Inline ranges (T9) tokenise a replaced line pair into identifier runs, punctuation and whitespace (so a YAML key and its value change separately), diff the tokens, and map token ranges to byte ranges in the line.

**Grid.** Inputs are pre-flattened `Arc` slices sorted by setting path. Swimlanes with the same effective hash are grouped first (many are identical), so an all-equal file returns at once; otherwise a k-way merge over the distinct groups builds rows and allocates only for rows that differ. Output is sorted by path and capped (`truncated` flag); 05 pages it.

**Search.** Blobs are deduplicated by hash and searched once (`search_slice`, `BinaryDetection::quit(0)`, CRLF-aware, `fixed_strings` for literals); each blob's capped hits are collected in parallel, then merged in (swimlane, path, line) order until the total cap, so truncation is deterministic. Line text is cut at 512 bytes on a char boundary and has no `\r`; ranges are byte offsets into that text.

**Secret scan.** Rules: private-key headers, known token prefixes (`ghp_`, `github_pat_`, `AKIA`, `xox[abp]-`, `glpat-`, `AIza`, `sk_live_`), JWT shape (`eyJ` plus two base64url segments), and long high-entropy strings (length and entropy thresholds in `ScanConfig`). Never fires on a key name, on a placeholder, or on a PEM `PUBLIC KEY` or `CERTIFICATE` block. A `SecretMatch` holds line, start column, length and rule, never the value; `marker()` formats `[REDACTED: N chars, rule]` so 06 and 07 do not each invent it. Thresholds are tuned after Q20 (A18).

**Batch, P5 and P6.** Batch functions take `&rayon::ThreadPool` (never the global pool), dedupe by content hash, parse and index each unique blob once, and collect with ordered `collect()`, never `for_each` into shared state. The P6 benchmark builds a 2-thread pool to stand in for 2 vCPU. `recompute_paths` is the P5 kernel: for each affected (swimlane, path) it recomputes drift, effective hash, the directory hashes up the ancestor chain, and the checks that depend on that file. Adoption ranking (D22): Jaccard similarity over (NFS path, normalised hash) pairs between the swimlane's tenant-suffixed files and each deployable branch mapped forward, tie broken by branch name; template branches are skipped by `BranchKind`.

**Benchmarks and fixtures.** Tests get the `small` fixtures by calling `xtask::fixtures::generate` into a temp dir (dev-dependency on `xtask`; needs `git` on PATH, as the generator does). Benchmarks use `target/fixtures/target`, generated by the same call when its `manifest.json` is missing. Git-side content (G) is read in bench and test support with the `git` command line (`ls-tree`, `cat-file --batch`), never in `src/`. The compare benchmark takes the largest YAML in swimlane 1 and a deterministic mutation of about 5% of its lines (identical inputs would measure nothing).

## Tests, benchmarks and fuzz targets

## Risks

- **Hostile input into parsers (S11, S22).** Alias bombs, deep nesting, huge scalars and pathological regexes are contained by size-based `Limits`, a node budget on alias expansion, linear-time `regex` with size limits, ten fuzz targets with hostile seeds, and `Display` and `Debug` that never echo input. Residual: tree-sitter is C code reading untrusted bytes in the hub process. It only receives input the Rust parser accepted under the limits, it is cancellable, and `engine_index_settings` runs it under the fuzzer's sanitizers; the residual risk goes in the threat model.
- **Secret values leaking (S13, S14b).** `SecretMatch` stores no value; messages and warnings use paths, lines and lengths; a planted-value test covers every output type. A false negative lets a secret through and a false positive blocks a save; both are tunable (A18).
- **Determinism versus parallelism (P6, acceptance 3).** Ordered collects, explicit pools, no clocks or maps with random order, enforced by source scans and a 1, 2 and 8 thread comparison.
- **Performance (P5, P6, P7).** The sharpest margins are `index_settings` (parse plus tree-sitter on 6,000 lines) and text search at 400 ms with two threads. Mitigations: parse once per unique blob, group identical swimlanes before the grid, search deduplicated blobs only, `Bytes` without copies. Benchmarks run at target scale with 2 threads; a miss is escalated with p50, p95, p99 and a flamegraph, never absorbed by loosening a threshold.
- **Scale of the work.** Ten tasks and ten fuzz targets; T4's interim merge rules are thrown away at T10 (A19). The largest unknowns are the real-snapshot run, which I cannot do (A4), and the byte-exact config-server fixtures, which I cannot obtain (A3).
- **Dependencies (S19).** New crates are small in number, pinned at least 14 days old and checked on 2026-10-13; the newest saphyr releases are refused for age, and tree-sitter 0.27 for the toolchain. A C compiler is needed to build tree-sitter.
