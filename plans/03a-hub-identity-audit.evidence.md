**Design choices the reviewer raised in round 1 and that were deliberately not implemented** (for the human; the reviewer's reasoning, not mine):

15. **The verifier does not enumerate the bucket.** It checks a bucket object only for a checkpoint row that exists. An owner who truncates the tail of `audit_events` and deletes the matching `audit_checkpoints` rows gets a clean run, although the bucket still holds the objects. Cheap fix: a bounded prefix `list` on `CheckpointBucket`, so the objects without a row are found. Now written in the threat model's residual risks.
16. **Random session cookies each cost one indexed read.** A client can send any number of random session cookies and each is looked up. Option: a bounded negative cache, or a WAF or ingress rate-limit note for prompt 09. Not done.
17. **No alert after N consecutive failed nightly runs.** `NightlyOutcome::Errored` and `NightlyOutcome::LeaseLost` only log and count, so a verifier that cannot run for weeks raises no notification.
18. **Rows the shipper cannot read are never sent to Cloud Logging** (`audit/shipper.rs`, near line 175). The shipper logs an error with the position, moves its cursor past the row and ships nothing for it, so the copy can lack an event.
19. **The nightly verification is not incremental, and its time at one million events is unmeasured.** It rereads the whole chain every night; with round 1 it also parses each event and reads 16 more columns per row. Item 5 still stands.
20. **One foreign malformed cookie hides all cookies** (`session/cookie.rs`, near line 88): the `Cookie` header parser refuses the whole header when any cookie in it is malformed, so one malformed cookie from another application on the same host name keeps the session cookie from being read at all.
21. **The first-sign-in notification is awaited inline, for up to 5 s**, after the transaction has committed. It delays the redirect, not the commit.
22. **`just verify` skips the Postgres-backed tests when Docker is missing** (it prints `SKIPPED` unless `LK_REQUIRE_DOCKER=1`), so a green `just verify` without Docker says little about them. `verify-03a` sets the variable.
