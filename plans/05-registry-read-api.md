## Design notes

Choices that shape the tests. Anything that needs a human is also in the ambiguity table.

**Shape.** `Registry::build(RegistryDeps)` returns the parts the hub composes: `AgentIngest` (`ReportSink`), `SentinelIngest` (`SentinelSink`), `RegistryService` (`RegistryRead` and `RegistryApi`), `AdoptionService`, `RegistryBlobPolicy`, `registry_routes`, `registry_route_specs` and `registry_jobs` (a list of `(JobSpec, Arc<dyn Job>)` for 03b's `JobRunner`). `RegistryDeps` holds a `PgPool` (the `lanekeeper_app` role), `Arc<dyn BlobStore | GitReader | EventBus | Leases | AuditLog | Users | AgentGateway | Notifier>`, a `Clock` and `RegistryConfig`. Nothing in this crate reads a clock or an environment variable directly, and every limit is a field of `RegistryConfig` with a tested default. Queries are runtime-checked `sqlx::query` with binds, as 03a and 03b do (the skill's `query!` needs offline metadata that the xtask harness does not have, A39); no SQL is built by formatting a string.

**Source and derived tables.** Source facts are written by ingestion (`blobs`, `file_observations`, the NFS columns of `file_state`, `services`, `service_state.pods`, `sync_windows`, `release_hints`, `sentinel_records`). Derived facts are written only by the pipeline and are reproducible from the source facts and Git: the drift columns of `file_state`, `effective_tree_hashes`, `effective_files`, `findings`, `swimlane_registry.state_counts`. The nightly job and the property test rely on that split. Baselines, adoption rows, marks and deployments are decisions (audited).

**Ingestion (T1).** `hello` checks that the identity's swimlane equals the payload's and that an admin created the swimlane (otherwise `IdentityMismatch`, A15), stores the agent version and mount facts, resets the per-swimlane stream state (bounded map) and returns `AgentConfig` (scan interval 10 s, heartbeat, `max_file_bytes` 2 MiB, the engine's default deny globs plus the admin's, the D88 environment allowlist, the swimlane's tenants). `heartbeat` compares the root with `swimlane_merkle` (root row): unknown gives `RequestFullScan`, equal gives `None`, different gives `RequestDelta{since_root: known}`; a pending `needs_full_scan` (spool gap, failed apply, A13) also gives `RequestFullScan`. `delta` validates before it stores anything: bytes present for a denied entry is `Invalid`; bytes whose SHA-256 differs from the entry's hash is `Invalid`; bytes over `max_file_bytes`, more than `MAX_DELTA_ENTRIES` entries or `MAX_DELTA_BYTES` bytes in one logical delta is `TooLarge`; a path that matches a deny glob is treated as denied whatever the agent said and its bytes are dropped (D79, S17 defence in depth); parts of one logical delta must agree on `base_root` and `new_root`. Non-final parts store their blobs (`BlobStore::put`, idempotent) and stage their metadata in `delta_staging` in one transaction, then return `Ok` (so 03b's acknowledgement is truthful and no acknowledged version is lost, P15). The final part applies the staged parts in chunks: for each path, an entry equal to the current NFS hash is skipped (idempotence), an older `observed_at` than the stored one is recorded in history but does not move `file_state` back, a first sight of a path in a swimlane that has no inventory yet is an initial observation (A11), and a changed path gets an observation (attribution decided by T7 rules, `during_job` from the delta), the NFS columns of `file_state`, one audit event if it is out of band, and a `FileObserved` outbox event, all in the chunk's transaction. Then the root, `agents`, `agent_acks` (monotonic) and `swimlane_registry` are updated in a last transaction and the staging rows are deleted. A per-swimlane advisory lock serialises applies. A crash between chunks is repaired by the agent's retry (the delta is not acknowledged until the last part is applied) because every step is idempotent. Out of band means: no `file_observations` row with source `tool_write` for the same (swimlane, path, hash) (`ToolWrites::explains`) and no sync window or `during_job` (A10).

**Pipeline (T3).** One lease (`registry-pipeline`, ttl 30 s, `max_run` 15 minutes) so one replica holds all `LaneState`s (about 25 MB for 40 swimlanes of 2,000 files: hashes and findings, never content). The job's `run` loops: reconcile first (cheap divergence scan, so events missed between runs or during a takeover cannot leave stale state), then select over the event stream and the coalescing timer until `ctx.ensure_held()` fails. Coalescing is per swimlane in 200 ms windows; the affected set is a bounded `BTreeSet` of paths per swimlane (over `max_affected_paths` it falls back to a full lane recompute); the windows of all swimlanes that closed are given to one `recompute_paths` call so that a base file shared by forty swimlanes is parsed once. Pairs come from `FileObserved` (the path), `GitHeadMoved` (`diff_trees`, then repo path to NFS path for every swimlane the branch concerns: the base default branch concerns all, tenant branch B concerns swimlanes with B in their tenant set; template and docs branches concern none), a baseline confirmation or intentional mark (the path, or the whole swimlane), and a rules fingerprint change (the whole swimlane). Git hashes for drift are normalised from Git bytes (the engine's `drift_hash`), cached by (repo, object id) so a nightly run reads each distinct Git blob once. The engine reads the bytes of only the groups it recomputes plus the root files (its documentation says so); `LaneLoader` loads exactly those through `BlobStore::get_many` and passes the right hash with empty bytes for the rest (verified by `incremental_never_needs_the_bytes_of_clean_files`; a failure is an escalation to 04, A21). Persistence is by diff: only changed `file_state` rows, directories, effective files and findings are written; findings are matched by a fingerprint (kind, path and the stable part of the detail), opened when new and resolved when gone; every transaction ends with its `DriftChanged` (chunks of 500 paths, at most 20 per batch and swimlane, A26) and `FindingsChanged` events. A mark that no longer holds (`mark_stale`) is deleted with one `DriftMarkCleared` audit event (system actor). Auto-baseline on convergence (N equals G, `set_baseline_to_nfs`) is persisted only once a swimlane is adopted; the batch writes one `BaselineAdopted` event with actor system and the path list in the bounded `diff` (A12).

**Reads (T6).** Authorization is two layers: the 15 routes are registered through `GuardedRouter` with `RouteGuard::Role(Viewer)`, and every `RegistryRead` method calls `authz::require_viewer(&User)` first (active, role at least Viewer; pending, disabled and role-less users are `Forbidden`), because MCP (07) calls the port without the router. Roles are global (D35), so there is no per-swimlane filter. The tree lists the direct children of a prefix from one aggregate query over `file_state` (range on `(swimlane_id, path text_pattern_ops)`, grouped by child name, keyset on the child name), then fetches the file rows of the page with `= ANY($1)`; a directory's `drift` is the worst state among its descendants. List ETags come from `swimlane_registry.version` plus the query; content, compare, effective and served ETags are content hashes. `history` pages `file_observations` on the existing `(swimlane_id, path, observed_at DESC, id DESC)` index. `search_settings` is one SQL statement: `settings_index` (trigram GIN on `setting_path`) joined to `file_state` on the current hash, with the swimlane and file filters, keyset on a surrogate. `search_text` collects the deduplicated current blob hashes of the chosen swimlanes (from a per-swimlane file list cached by `swimlane_registry.version`), gets the bytes through `BlobStore::get_many` in batches of 1,000, builds an engine `SearchCorpus` (cached per set of swimlane versions) and runs `engine::search_text` on a rayon pool inside `spawn_blocking` with a `CancelFlag` set after 5 seconds, caps clamped to the server ceilings (A27), and reports truncation. `grid` uses the effective configs of the chosen swimlanes (moka, keyed by the effective hashes in `effective_files`) and `engine::grid`; `compare` caches the diff by the two blob hashes; `compare_tree` between two swimlanes walks `effective_tree_hashes` and `effective_files` and skips equal subtrees, counting them; other combinations use a path-level hash comparison without skipping (A29). Locations (line ranges) come from `settings_index` and the engine's findings. Flagged values are masked as `[REDACTED: N chars, rule]` in the setting-value surfaces (A28).

**Attribution and windows (T7, T8).** Order as in the domain model: tool write (certain), sentinel record within +-60 s of the observation (high; actor from the OS Login map or an unambiguous email match, else `Actor::OsLogin`), observation inside a sync window or with `during_job` (high), `nfs_client` (medium, only after a 30 s grace and only for a swimlane whose sentinel has been seen since the change), otherwise unknown. `Attribution::may_upgrade_to` is the only gate: a strictly higher confidence replaces, an equal one never does. Sentinel batches larger than `max_batch_records` are `TooLarge`; `Attribute` operations are acknowledged and not stored (A16).

**Security notes.** Every handler and port method authorizes first; all SQL is bound; log fields are ids, paths, hashes and counts, never contents, setting values, environment values or secrets (a log-capture test plants secret-looking values in files, settings, environment values and secret-scan hits and asserts none reaches a line); errors map to the closed `ApiError` set with no SQL or path text; the hub never trusts an agent flag where it can check (denied, hash, size); the adoption secret scan stores locations and lengths only; the environment values stored are only those on the D88 allowlist, whatever the agent sends; the `served` call uses `AgentGateway` with a timeout and is rate limited per swimlane; no component sends user content to an LLM (S15).

**Performance notes.** Hot paths and where each budget is spent: ingestion is one INSERT per chunk with `unnest` arrays and one `= ANY` lookup of current hashes; the settings index runs after the ack on a bounded queue with a rayon pool of `registry_pool_threads` (default 2), so the ack rate is not tied to parse time; the pipeline writes only the diff; reads never parse YAML (they read `settings_index`, `effective_files` and `file_state`); caches are weighted and bounded (default 256 MiB for parsed and rendered values in all, on top of 03b's blob cache); no `OFFSET`, no query without a `LIMIT` except aggregates bounded by `MAX_LANE_FILES`; every hot query has an `EXPLAIN (FORMAT JSON)` snapshot taken on a database seeded to target scale and analysed (the snapshot keeps node types and index names, not costs).

## Tests, benchmarks and fuzz targets

**Unit and table tests.** Branch classification (including the admin patterns), the cursor codec (round trip, tampering, 1,024-byte paths), query parsing bounds, the fingerprint of a finding, the dirty-set and Git-path mapping, the OS Login to user matching (ambiguity gives no match), the correlation order, the retention plan, the Merkle root store, the delta assembler (every illegal part sequence).

**Property tests (proptest).** Incremental equals full (Acceptance 2); GC never deletes a referenced blob; branch classification is total and exclusive; cursor encode-decode is the identity and decode never panics; attribution only ever moves up in confidence whatever the order records and observations arrive in; coalescing never loses an affected path; replaying any prefix of a delta sequence twice gives the same tables.

**Golden and snapshot tests (insta).** `EXPLAIN (FORMAT JSON)` of every hot query; the JSON of each published event (envelope and chunking); the problem bodies of the read routes; the swimlane detail and tree responses on the small fixtures.

**Integration tests against real Postgres 16.** testcontainers with the digest-pinned image that 03a and 03b use (or `LK_TEST_PG_ADMIN_URL`), migrated as `lanekeeper_migrator` including `0003`, the hub side connecting as `lanekeeper_app`, so a missing grant fails a test. `LK_REQUIRE_DOCKER=1` (set by `verify-05`) turns a missing daemon into a failure. The port suites run against the real implementations: `ports::conformance::{registry_read, report_sink, sentinel_sink}` through a `RegistryScenario` and a `SentinelProbe` over the test rig. The target-scale tests and benches use `cargo xtask gen-fixtures --scale target` (40 swimlanes, about 80,000 files, 60 tenant branches), loaded through the real ingestion path; Git is `ports::fakes::FakeGit` loaded from the fixture repositories, never `GixReader`.

**Fuzz targets (own crate `crates/hub-registry/fuzz/`, own lockfile, as 02, 03b and 04 did; the root `fuzz/` crate is the domain's).** `registry_delta` (a sequence of `ScanDelta` parts, T1: never panics, memory stays within the configured bounds, an accepted logical delta equals the entries given, bytes are never stored for denied or mismatching entries), `registry_cursor` (T6: decode never panics, accepted cursors re-encode to themselves), `registry_query` (T6: every query-string shape of the 15 operations either yields a bounded typed query or a 400), `registry_sentinel_path` (T7: any path string either maps to a clean `NfsPath` of the swimlane or is dropped; no traversal form survives). **Benchmarks (criterion, registered in `perf/budgets.toml`).** The harness benches write `target/perf-results/<name>.json` in the `{bench, unit, values}` shape the engine and agent use. ## Risks

1. **P5 and P7 at target scale are spent in database round trips, not in the engine.** The engine kernels already fit their budgets alone (04). The mitigations are the in-memory `LaneStore`, diff-only writes, batched `= ANY` reads, `unnest` inserts and a tree that never touches blob content. If a P7 line still misses at target scale, I stop and escalate with the p50, p95 and p99, a flamegraph or `EXPLAIN` and the options (an index, a `swimlane_registry` counter, a smaller default page).
2. **P15 against the audit chain.** An out-of-band version costs one `AuditLog::record` (3 ms p95 under contention, P12), so 1,000 replayed versions per second is only reachable if the records of a chunk share a transaction and the chain lock. The bench `ingest_versions_per_s` measures it with audit included. If it misses: write the audit event for the newest version of each path and record the skipped intermediate versions in its `diff` text (history keeps all of them). That changes what D38 promises, so it would be a decision, not a quiet fix.
3. **Text search with a cold blob cache.** 23,000 distinct blobs are about 230 MB; 400 ms is reachable only warm. The bench reports warm and cold, the corpus is built once per set of swimlane versions, and a first-search warm-up reads the current blobs through `BlobStore` in batches. If cold misses the budget this is an escalation, not a loosening.
4. **Breadth of the contract PR.** 0003 adds a dozen tables and columns, one event, possibly a finding kind, two notification kinds and six budgets, and touches 03b's `sse.rs`. Mitigation: everything is additive, each item names its task and its proof, and A1 to A3 and A35 can be approved or declined row by row (each decline has a stated fallback).
5. **Single pipeline leader.** All derived state is computed on one replica at a time. Takeover costs a lazy full recompute per swimlane (about 4.5 s each at design scale, P6 / 40) after the reconcile scan, so a failover can delay drift by seconds to minutes for a swimlane nobody touched; reads keep serving the persisted state meanwhile. Per-swimlane leases were rejected because `JobRunner` allows 64 jobs and swimlanes grow.
6. **Memory (P11).** `LaneState`s (about 25 MB), the settings-index queue, the normalised-hash cache (about 20 MB) and the weighted caches (256 MiB default) are bounded by configuration; a test builds the target-scale state and asserts the bound on the registry's own structures.
7. **Security.** The largest exposures are the read surface (authorization on both the route and the port, S4), what is logged or returned from file contents (S10, S14b, A28), the hub accepting bytes or flags from an agent (checked, A10 to A14), and the adoption scan (locations only, S13). The unmasked raw text, blobs and diffs are a residual risk that the threat model will state and that 06 and 08 must decide on.
8. **Depends on neighbours' behaviour that is not yet written.** 06's `record_tool_write` call (A10) and `last_notified_at` write (A20), 17's sentinel path layout (A17), and 03a's real `AuditLog` (tests use a minimal `AuditLog` over the real transaction until the composition exists). Each is a named seam with a test on this side.
