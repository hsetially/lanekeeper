## Design notes

These are the decisions that shape the tests. Anything that needs a human is also in the ambiguity table.

**Flow.** `main` builds `Settings`, opens the cap-std root, joins (T2), then `Session` runs: Hello, wait for `AgentConfig` (30 s), full `ClusterReport`, immediate heartbeat, then select over scan ticks, hub commands, k8s events and the outbox. Every hub message goes through `proto::convert::ToAgent::from_proto` before anything else; a message that fails validation is dropped and counted. A command that fails validation but has a parseable request id is answered with a failed `OpResult`.

**Two delta paths, one `seq` counter.** (a) Agent-initiated: a scan finds changes, the `Quiescer` (T10) releases them, versions are appended to the spool (T9), the sender turns them into `ScanDelta` messages, `Ack` deletes them. (b) Hub-initiated: `RequestDelta`/`RequestFullScan` is answered from the tree, not from the spool, with fresh `seq` values, and is not spooled (the hub asks again if it gets no ack). `seq` is persisted by the spool so it never repeats across restarts. Tool writes update the tree at once and are not spooled; the hub recovers them through the root mismatch on the next heartbeat. Before T9 the direct sink sends from memory.

**Delta consistency.** File bytes are read through cap-std at send time and re-hashed. If the bytes differ from the tree's hash, the tree is patched with the hash of the bytes actually sent, and `new_root` is computed afterwards. So every entry satisfies `hash == sha256(content)` and `new_root` matches the entries. A full listing is streamed message by message (bounded channel, no whole-tree buffer).

**Walker.** An own parallel walker over the cap-std `Dir` (explicit rayon pool, 4 threads, never the global pool; blocking work in `spawn_blocking`). `globset` does the ignore and deny matching. No symlink is followed; hidden files and `.gitignore` have no special meaning (D16: every file is tracked). A directory that fails to read keeps its previous subtree and counts an error: a scan error never becomes a removal. An empty root after a non-empty tree is held until the 30 s max deferral (a dropped mount must not look like mass deletion). Names that are not valid `NfsPath`s (non-UTF-8, backslash, control characters) are hashed into the tree by raw bytes and reported as a `SkippedEntry` on the parent directory with reason `unrepresentable_name`.

**Merkle encoding** (domain-model.md leaves the bytes open). Directory hash = SHA-256 over, for each entry sorted by raw name bytes: `u32_le(name length) || name || kind byte (0 file, 1 directory, 2 other) || 32-byte child hash`. File hash = SHA-256 of the content. Symlinks and special files: kind 2 with an all-zero hash. A file over the size cap or a denied file is hashed by streaming (denied: up to 64 MiB, larger: kind 2). Empty directories are nodes (an empty directory changes the root; C11 needs it). `merkle_encoding_golden` (insta) pins the bytes, because 05 may need to reproduce roots.

**Root ring.** Persistent nodes (`Arc<DirNode>`), so a new root shares unchanged subtrees. Bounded by age (1 hour), count (512 roots) and retained bytes (16 MiB); eviction is oldest first. An unknown `since_root` gets a full listing.

**Timing and P1.** Walk 10 s, heartbeat 10 s, quiet 3 s, max defer 30 s are `Tunables` with an injected `Clock`. A change is released when the tree has been quiet for 3 s. The quiet clock for a change starts at max(file mtime, previous walk), capped at the detection time, so a change that was already finished when a walk finds it is released at once instead of waiting another 3 s. While changes are pending, the agent runs a full stat walk every 1 s instead of every 10 s (a burst, bounded by the 30 s max deferral), so a copy that keeps creating new files keeps pushing the deadline and ends up in one delta. Clock skew between the NFS server and the node can make the agent release up to 3 s early or late; that only changes batching, never correctness, because bytes are re-hashed when read and a later change is reported by the next walk. Latency of one finished change: about 10 s (walk phase) + walk time + hash and send, so 11 to 12 s worst case; a change still being written is released 3 s after its last write plus up to 1 s of walk granularity. Headroom against the 15 s budget is about 3 s. Hub `AgentConfig` values are clamped: scan 5-300 s, heartbeat 10-300 s (never faster than 10 s, which would break P3), max file size at most 2 MiB, deny globs added to the defaults, never replacing them.

**Error mapping** (the proto has five codes). Hash mismatch: `CONFLICT` with `current_hash`. Missing file or parent directory: `NOT_FOUND`. Traversal, symlink, deny glob, namespace not allowed, failed validation: `DENIED`. Not a regular file, over 2 MiB, unknown command: `UNSUPPORTED`. Anything else from the OS: `IO`. A `FetchServed` that hits the agent's own rate limit: `ServedResponse` status 429 with an empty body; a connect failure or timeout: `OpResult` `IO`. Error replies carry codes only, never paths or OS text; the detail goes to the log (paths and hashes only).

**Config variables** (T1 lists seven items; the rest are needed by Hello, TLS, the spool and T6/T12). All `LK_`-prefixed: `HUB_ENDPOINT`, `HUB_AUDIENCE`, `HUB_CA_FILE`, `SWIMLANE`, `CLUSTER`, `PROJECT`, `NFS_SERVER`, `NFS_EXPORT`, `NFS_ROOT`, `CERT_SECRET`, `JOIN_TOKEN_SECRET` (optional), `JOIN_MODE` (`auto`, `workload-identity`, `token`; default `auto`), `NAMESPACES` (comma list, at most 64), `SPOOL_DIR`, `SPOOL_MAX_BYTES` (512 MiB), `SPOOL_MAX_ENTRIES` (100,000), `TMP_DIR`, `IGNORE_GLOBS` (added to `.nfs*` and `.lanekeeper-tmp-*`), `SYNC_JOB_NAME_GLOBS` (default `*dataload*`), `SYNC_JOB_LABEL` (optional `key=value`), `HELM_HINT_CHART_GLOBS` (default `csp-tenant-data-*`), `CONFIG_SERVER_URL` (for example `http://csp-configuration-server.<ns>:8888`), `CONFIG_SERVER_DEPLOYMENT` (`namespace/name`, for the pod start time), `METADATA_URL` (default the GCE metadata host), `HEALTH_ADDR` (default `0.0.0.0:9090`), `POOL_THREADS` (4), `LOG` (level).

## Risks

Security:

1. **Walker and cap-std (S17), A1.** The prompt contradicts itself. The default keeps all access inside the root; cap-std still follows symlinks that stay inside the root, so "no symlinks" is enforced by an explicit no-follow open per component, with a small TOCTOU window inside the root only. The fuzz invariant is "never touches anything outside the root".
2. **Key material and Secrets (S5, S7, S17).** The private key sits in the certificate Secret, readable by anyone with `get` on it; the join-token read widens RBAC (A2). Generated key bytes pass through `rcgen` and tonic buffers that cannot all be zeroized (residual risk, stated in the threat model). Tokens are `Secret<String>` and never formatted.
3. **The hub is semi-trusted input.** Commands, globs, intervals and the env allowlist are validated and clamped; a compromised hub still can read any non-denied file and write with a correct hash. Deny globs cannot be removed by the hub. The config-server endpoint has no authentication (Q37): called only on command, never with a host taken from a message.
4. **Denied bytes leaking** through a path nobody thought of (spool file, log, metrics). One capture test watches the stream, the spool directory and the logs for planted marker bytes.
5. **Supply chain (S19).** Many new dependencies (kube, k8s-openapi, aws-lc-sys, X.509 parser, prometheus-client). Each needs age >= 14 days, `cargo deny`, `cargo audit`; a new advisory may need `.cargo/audit.toml` (not requested now; I will escalate rather than edit).

Performance:

1. **P1 headroom is about 3 s (A6).** The 10 s walk phase alone uses two thirds of the budget; the quiet-from-mtime scheme and 1 s pending walks are what keep the rest small. The real-timing test is the judge. The pending-state walks are a CPU burst (up to 30 s per change burst), outside the steady state that P4 measures.
2. **P4 memory (64 MiB).** Reflector caches, the root ring and in-flight 3 MiB messages compete. Mitigations: objects trimmed on ingest (no managedFields), paged initial list, ring bounded at 16 MiB, at most 4 unacked messages in flight, 2 runtime workers, a 4-thread pool, bounded blocking threads. Measured by the steady-state harness.
3. **P3 margin (estimated 500-700 of 1,024 B).** Any extra periodic traffic breaks it: heartbeat clamped to >= 10 s, keepalive 30 s, no periodic cluster report.
4. **P15 throughput and fsync cost.** Group commit (one fsync per released batch), sequential segment reads, batches built by streaming. A non-fixture NFS or disk may behave differently from the local bench.
5. **Local benches do not include NFS latency** (A15); the stat walk over real NFS may exceed 1 s and needs the pilot numbers.
