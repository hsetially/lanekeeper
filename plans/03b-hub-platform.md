## Design notes

These shape the tests. Anything that needs a human is also in the ambiguity table.

**Crate split.** `hub-platform` is a library of the components plus their tonic and axum handlers. `hub` composes them and owns everything that is about the process: the listeners, the headers, the limits, the static files, shutdown and telemetry. A hub instance is `Hub::build(Deps)`, where `Deps` is the set of ports (`Arc<dyn ...>`) plus settings, so that the three-instance tests build three hubs in one process on real Postgres, with fake agents, the `ports` fakes for what 03a and 05 will provide, and a software KMS.

**Ports used before their owners land.** `TokenVerifier` and `AuditLog` (03a), `ReportSink` and `SentinelSink` (05) are consumed through the `ports` fakes in tests. The hub binary needs real ones; until 03a and 05 merge, `main` refuses to start without them rather than falling back to a fake (a fake in production would be a hole). The binary therefore compiles and runs its own integration tests with fakes, and the final wiring is a small follow-up in each owner's PR (A5).

**Routes and S4.** Platform routes: `GET /api/v1/events` (Viewer), `GET /api/v1/blobs/{hash}` (Viewer), `POST /hooks/github` (`Guard::Public`, reason: verified by HMAC and replay guard), plus gRPC services on separate listeners (not HTTP routes: authenticated by mTLS SAN, and each RPC checks its kind of identity). `/healthz`, `/readyz`, `/metrics` live on the internal listener only and are listed in `Allowances` with that reason. `platform_route_table_is_guarded_and_matches_openapi` calls `ports::conformance::assert_route_table` against `api/openapi.yaml` for exactly these routes.

**Listeners.** (1) Web: HTTPS, TLS 1.3, axum, behind the users' HTTPS load balancer (D25). (2) Agent and sentinel: tonic over a rustls acceptor built here, TLS 1.3 only, client certificate optional at the TLS layer so `Join` works without one, then required by every other RPC through the peer identity (a certificate's SAN prefix decides whether it may call `Agent` or `Sentinel`; one is never accepted on the other). (3) Replica: internal `Forward` RPC, own TLS config with its own CA key, so an agent certificate cannot even complete a handshake here. (4) Ops: plain HTTP on a cluster-internal port, no secrets, read-only.

**Certificates.** The CA certificate is public and is provisioned once by an offline ceremony: `hub ca-init` reads the public key through the inherent `CloudKmsSigner::public_key`, builds a self-signed CA certificate signed through `KmsSigner`, and prints the PEM. Runtime issuance loads only that PEM. rcgen is given a `SigningKey` implementation that calls `KmsSigner::sign_digest` over the SHA-256 of the to-be-signed bytes; rcgen's signing hook is synchronous, so issuance runs in `spawn_blocking` and bridges with `Handle::block_on`. Leaf keys are generated by the requester (agents send a CSR). The hub's own server certificate and each replica's certificate are generated in memory at start-up with a fresh key and signed the same way, renewed at half their 24-hour life. No code path loads a private CA key (acceptance 3, see the traceability row).

**Join.** The CSR is checked for a valid self-signature (proof of possession), P-256, bounded size. Its subject and SAN are ignored: the hub builds the SAN from the validated swimlane id (`TenantId`-style typed parse) or sentinel name, `kind` picks the prefix, EKU is client auth only. Google path: `TokenVerifier::google_id_token(jwt, hub_audience)`, then `subtle` equality of the token email with `swimlanes.agent_service_account` (a swimlane with none registered cannot join this way). Token path: only when the swimlane has an unexpired unused token; the presented token is hashed with SHA-256, compared with `subtle` against each candidate hash of that swimlane (at most a handful), then consumed by one atomic `UPDATE`; a failed attempt costs the same time as a successful lookup. Both paths write `AgentJoined` in the same transaction as the token use (the Google path writes the audit event alone). Every failure returns the same `Unauthenticated` status with no reason; the reason goes to the log as a code. Join attempts are limited per swimlane and per peer address, bounded in memory.

**Connect.** The identity comes from the verified peer certificate, never from the message. The first message must be `Hello`, within 10 s, with `swimlane` equal to the certificate's; anything else ends the stream. Decoding goes through `proto::convert`, so size, enum and path validation happen before a domain value exists. Hub to agent: bounded queue per stream (64), per-agent in-flight cap (16, `GatewayError::Busy` above it). The stream handler calls `ReportSink` for `Hello`, `Heartbeat`, `ScanDelta` and `ClusterReport`; replies to commands (`OpResult`, `FileContent`, `ServedResponse`, `NotifyResult`, and a `ClusterReport` that carries a `request_id`) are routed to the waiting caller by request id. A reply with an unknown or already-answered request id is dropped and counted. `RequestDelta` and `RequestFullScan` carry no request id and have no reply message; `AgentGateway::request` writes them to the stream and returns `AgentReply::Op{ok: true}` with the id `ack`, which is what the `ports` fake does (the agent answers with `ScanDelta` messages that go to `ReportSink`).

**Routing (D62).** `agent_connections` is keyed by swimlane. Connect runs `INSERT ... ON CONFLICT (swimlane_id) DO UPDATE SET epoch = agent_connections.epoch + 1, replica_id, replica_address, connected_at, last_seen_at RETURNING epoch`. Disconnect does not delete the row: it sets `replica_address = ''` where the epoch still matches, so the epoch stays monotonic. A `DELETE` would let a later connect reuse epoch 1 while a stale replica still holds epoch 1 and clears the new row. A row with an empty address, or a `last_seen_at` older than 30 s (owner refreshes every 10 s), means not connected. `request()` reads the row (cached for 1 s per swimlane in moka, invalidated on local connect and disconnect), uses the local stream when `replica_id` is this replica and the epoch matches the local stream's, and otherwise calls the owner's `Forward` RPC with the epoch it read. The owner refuses a forward whose epoch is not the current local stream's epoch (`FAILED_PRECONDITION`), and the caller re-reads once and retries once (the agent may have moved), then fails with `NotConnected`. When a stream is replaced or closed, every pending request on it completes with `GatewayError::Closed`. Every call has a timeout (the caller's, capped), the pending table is bounded per stream, and the forward channel pool is bounded. `status()` is `Connected` for a live row, `Disconnected` when the agent has joined before, `NeverSeen` otherwise (from `agents.joined_at`).

**Replica RPC.** A private proto, `crates/hub-platform/proto/replica.proto` (A6): `Forward(ForwardRequest{swimlane_id, epoch, timeout_ms, command: lanekeeper.agent.v1.HubMessage}) returns (ForwardReply{oneof reply: AgentMessage | error code})`. It reuses the contract's `HubMessage` and `AgentMessage` by import, so a command is validated by the same `proto::convert` on both sides. Replica identity is the `spiffe://lanekeeper/hub/<replica_id>` SAN, checked on the server; peers are found through the `agent_connections.replica_address` that each replica wrote itself (the headless-service DNS name of its pod). The `Forward` server accepts only requests whose SAN prefix is `hub/`.

**Events and the outbox (P13, D80).** All events, `publish` and `publish_in_tx`, are rows in `outbox` (A11), so that every event has one cluster-wide, ordered id; that id is the SSE event id and what `Last-Event-ID` resumes from. The table's trigger issues `pg_notify('lanekeeper_outbox', id)` on commit, so a rolled-back transaction emits nothing. Each replica has one dedicated `LISTEN` connection. On each notification (and on a 250 ms safety tick) the relay reads `WHERE id > cursor ORDER BY id LIMIT 500`, and also re-reads a short overlap window of ids below the cursor, because a transaction with a lower id can commit after one with a higher id and a naive cursor would skip it. A bounded set of recently relayed ids (the overlap window plus slack) removes the duplicates, so each subscriber sees each id once. A listener reconnect gives every subscriber a `Resync` and resets the cursor to the newest id. Payloads are the existing `DomainEvent` JSON (ids and hashes only, no content), size-capped at 4 KiB; the NOTIFY itself carries only the row id (the 8,000-byte NOTIFY limit never applies). Subscribers: each `subscribe` gets a bounded queue (256); a full queue drops that subscriber's backlog and delivers `Resync` first (it never blocks the relay or other subscribers). SSE replay reads `WHERE id > $last AND created_at > now() - 5 minutes` with a `LIMIT`; a `Last-Event-ID` older than the window, or unknown, gets a `resync` event first. `published_at` stays NULL: every replica reads every row, so there is no single "published" moment; the prune job deletes rows older than 1 hour, which is what keeps `outbox_unpublished_idx` small. If measurements show NOTIFY plus the relay missing P13, the prompt's escalation applies (measurements first).

**SSE.** Authentication through `SessionAuth` (A5). The filter is the user's query (swimlanes at most 64, kinds at most 15) intersected with `EventVisibility` (A10). Heartbeat is a comment frame every 15 s. Per user at most 5 streams, globally at most 2,000 (bounds are settings). The stream ends within 30 s of the user's session ending or role dropping below Viewer (the handler re-checks on the heartbeat tick through `SessionAuth::still_valid`), and on shutdown with a `retry` hint. Event data is the `DomainEvent` JSON, never file content; the event name is the `EventKind` wire name.

**Leases (D62, D63).** One `INSERT INTO leases (...) VALUES (...) ON CONFLICT (name) DO UPDATE SET holder = excluded.holder, expires_at = excluded.expires_at, fence = leases.fence + 1, acquired_at = now() WHERE leases.expires_at < now() RETURNING fence`; zero rows returned means another holder. Renew is `UPDATE ... WHERE name = $1 AND holder = $2 AND fence = $3 AND expires_at > now()`. The expiry uses the database clock, not the replica's. The port's `LeaseGuard` does not expose the fence (A4); the guard's private token is the fence, and platform jobs that write must still check `is_valid()` first. Jobs under leases: Git poll (60 s), `git_tree_index` persistence, outbox prune (10 min), `webhook_deliveries` prune (daily, 7 days), and the hooks that later prompts register (nightly recompute, checkpoints) through `JobRunner::register`.

**Git (P2, S18).** Mirrors live at `<LK_MIRROR_DIR>/{base,tenant}.git` on the replica's own volume, created on first start by a full bare fetch (`+refs/heads/*:refs/heads/*`, `+refs/tags/*:refs/tags/*`). `gix` calls are blocking and run in `spawn_blocking` with a timeout; one fetch per repo at a time (single-flight), with a coalescing queue of pending branch names. `GitReader` is implemented synchronously as the port says; `tree_index` caches in moka and the leaseholder persists new commits to `git_tree_index` (hash column is the SHA-256 of the blob, so the index is computed here once per commit, with rayon in `spawn_blocking`). `read` returns `None` for a missing path and `NotFound` for a missing commit; a missing commit triggers one read-through fetch before it is reported. `RepoPath` and `GitRef` are typed before they reach `gix`; no ref string is passed through unchecked. Fetch credentials come from `GitCredentials` and are handed to `gix` through its credential helper hook in memory, never in a URL, a command line, an environment variable or a log line. User tokens are never used (D41/D42 are 06).

**Webhooks (D64, S18).** Order is fixed: 1. body cap (4 MiB, S11) and read the raw bytes; 2. `X-Hub-Signature-256` HMAC-SHA256 over them with the secret from `SecretSource`, constant-time compare (`hmac` verify or `subtle`), failing with a bare 401; 3. `X-GitHub-Event` must be `push` or `pull_request` (`ping` answers 200; anything else 202 and ignored); 4. replay guard: `INSERT INTO webhook_deliveries ... ON CONFLICT DO NOTHING`, a conflict is a 202 duplicate and does nothing; 5. strict parse. For `push`: `repository.full_name` must match a configured repo, `ref` is a valid `GitRef` under `refs/heads/` or `refs/tags/`, `after` is a hex commit id; deleted refs are ignored. The handler enqueues a fetch (bounded queue, coalesced) and returns 202; the background worker fetches, then publishes `GitHeadMoved{repo, branch, from, to}` (`from` is the head before the fetch). Every replica's `MirrorSync` fetches on `GitHeadMoved` too (single-flight, so the receiver does not fetch twice), and a consumer on a replica that lacks `to` gets it through the read-through fetch. Delivery is at least once and consumers are idempotent (tree diffs). A queue overflow is dropped and counted: the 60 s poll catches it. The hub itself does no source-IP check: the load-balancer allowlist (S18, 09, Q28) is that control and the HMAC is the proof of origin; the threat model says so.

**Blob store (P7).** `put` computes `content_hash`, rejects over 4 MiB (`TooLarge`), then `INSERT ... ON CONFLICT (hash) DO NOTHING`; the bytes go in the cache only on a successful read, not on write (writes are often never read again). `get`: cache, then `SELECT content FROM blobs WHERE hash = $1`, populate. `get_many`: cache hits first, then one `WHERE hash = ANY($1)` for the rest (at most 1,000), result in the order first requested. The cache is moka with a weigher on `Bytes::len()`; default 512 MiB, setting `LK_BLOB_CACHE_MIB`. The endpoint returns the bytes with `Content-Type: application/octet-stream`, `X-Content-Type-Options: nosniff`, `Content-Disposition: attachment` (a blob is never rendered as a page, S12), `ETag: "<hash>"`, and the route class `immutable_private`. It never serves a hash that the registry marks denied or withheld: that decision belongs to 05, so the endpoint takes an `Arc<dyn BlobPolicy>` seam (a trait in this crate, default allow-all in tests, 05 supplies the real one; A13).

**Sentinel and acks (T11, D72, D74).** `Sentinel.Join` is the same CA path with `kind = Sentinel`: the ID token's email must equal `sentinels.service_account` for the VM name in the request; an unknown VM or a NULL service account fails identically. `Report` requires a `spiffe://lanekeeper/sentinel/<name>` SAN; `SentinelHello.vm` must equal the SAN name. After `SentinelHello` the hub sends `settings`; each `AuditRecordBatch` goes to `SentinelSink::records`, and only the returned `AckSeq` is sent as `acked_seq`. Agent acks: `AckWriter` sends `Ack{seq}` after `ReportSink::delta` returned `Ok`, never before, in the order the deltas arrived; a failed `delta` sends no ack (the agent keeps the version in its spool and resends), and a continuation message of a multi-part delta is acked as the sink accepts it. `agent_acks` is updated by 05's sink; the hub does not write it.

**Operations (T1).** Request pipeline, outermost first: request id and tracing span, RED metrics, security headers, shutdown drain gate, limits (per-IP bucket first because it is cheaper, then body cap 4 MiB, timeout 30 s, JSON depth 64), then the router; per-user buckets are applied after `SessionAuth` resolves the user. Buckets are moka caches with a time-to-idle and a maximum capacity (a flood of new IPs evicts old buckets, it does not grow memory). The client address behind the load balancers is the rightmost-minus-N entry of `X-Forwarded-For`, with N from a setting (`LK_TRUSTED_PROXY_HOPS`, default 1); with no header the socket address is used. Health: `/healthz` is process liveness; `/readyz` is Postgres reachable, mirrors opened, outbox listener connected. Metrics: `prometheus-client`, labels are route template and status class only, never user, path parameter or id. Tracing: JSON logs; spans carry ids, never bodies, headers or query strings. The OTLP exporter is off unless `LK_OTLP_ENDPOINT` is set (A9). Graceful shutdown (`SIGTERM`): readiness fails first, a 5 s grace for the load balancer, then new connections stop, SSE streams get a final `retry:` frame and close, agent streams close with a status that tells the agent to reconnect elsewhere, in-flight requests finish within 25 s, then exit. The agent endpoint closing releases `agent_connections` rows for this replica (epoch-guarded).

**Headers (S12).** Two classes of response get the full CSP: HTML (`index.html` served from `web/dist` with the nonce inserted into the `__CSP_NONCE__` placeholder, so 08's build must emit that placeholder; recorded for 08) and everything else gets the restrictive API policy. HTML: `default-src 'none'; script-src 'self' 'nonce-<n>'` (no `strict-dynamic`, no `unsafe-inline`, no `unsafe-eval`); `style-src 'self' 'nonce-<n>'`; `img-src 'self' data:`; `font-src 'self'`; `connect-src 'self'`; `worker-src 'self'`; `frame-ancestors 'none'`; `base-uri 'none'`; `form-action 'self'`; `object-src 'none'`; `require-trusted-types-for 'script'`; `trusted-types lanekeeper-docs lanekeeper-monaco` (names agreed with 08, A14). Also `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Strict-Transport-Security: max-age=63072000; includeSubDomains`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` denying everything, `Cache-Control: no-store` on HTML and API, `immutable` only on hashed assets and blobs. Monaco needs `blob:` workers and inline styles in some builds; S12 and "no third-party origins" win, and any such need is 08's to record in `design/DEVIATIONS.md`, not a relaxation made here.

**Observability of the platform.** Counters and histograms for: gateway requests by outcome, forwards by outcome, active agent streams, SSE subscribers and drops, outbox relay lag (newest id minus cursor), lease holds, webhook outcomes, fetch duration, blob cache hits and misses, Google API calls by operation and outcome. None carries a swimlane id or path as a label (cardinality is bounded by design: swimlane id appears only in logs).

## Risks

**Security**

- **The CA is the hub's whole trust root.** Mitigations: the key never leaves KMS and is used only through `KmsSigner` (a source scan, a type-level constraint and spies prove it); 24 h certificates; SAN built by the hub, never copied from the CSR; separate CA keys for agents and replicas; every SAN prefix checked per service; no revocation list, so a stolen agent key is good for up to 24 h (residual risk, in the threat model, mitigated by the audit trail and by disabling the swimlane's registered service account, which stops renewal).
- **The webhook is the one unauthenticated HTTP route.** Mitigations: HMAC over the raw body before anything else, constant time, a bare 401, bounded body, replay guard in Postgres, strict typed parse, a bounded and coalesced fetch queue so a flood cannot cause fetches without bound; the load-balancer IP allowlist is S18's other half and belongs to 09.
- **Event and log leakage.** Events carry ids and hashes only; the log-capture test drives every path with planted secrets; metrics labels are route templates only.
- **Join abuse.** Join attempts are limited per swimlane and per address, failures are indistinguishable, tokens are hashed and single-use, and the audit event is in the same transaction as the use.
- **A bad request id or replayed reply** crossing swimlanes: a pending table per stream, keyed by request id, so a reply can only complete a request on its own stream.
- **Dependency exposure** is larger than any earlier prompt (gix, OpenTelemetry, rustls roots, sqlx TLS). Each is pinned at least 14 days old, justified in the PR, and checked by `cargo deny` and `cargo audit`; A15 and A16 are the two places where I expect to stop.

**Performance**

- **P13 depends on LISTEN/NOTIFY plus the relay.** The design reads rows by id after each notification, so a missed NOTIFY costs at most the 250 ms safety tick. The bench runs three real hubs on real Postgres with 100 subscribers each. If it misses, the prompt's escalation applies, with measurements and the alternative (a replica-to-replica push over the existing mTLS channels).
- **The outbox overlap window** costs one extra indexed range read per notification. It is bounded by the window (10 s of ids) and the 500-row limit; the cost is measured in the P13 bench.
- **P2 includes a real fetch.** Webhook to event includes a `gix` fetch over the file transport in tests and HTTPS in production; the production leg is not measured in CI (no network), so the bench proves the hub's share and the threat to the budget is GitHub or network latency, which the 60 s poll bounds at 75 s.
- **Blob cache at 512 MiB with `Bytes` values** can hold more than the weigher counts if buffers are over-allocated. Values are stored exactly as read (`Bytes::from(Vec)` with the vector's capacity trimmed), and the memory harness measures resident size, not only the weigher's total.
- **Synchronous Git and CPU work** (tree indexing) must never run on the async executor; every `gix` call and the rayon hashing are inside `spawn_blocking`, with a bounded blocking pool use; a benchmark on target-scale fixtures (`diff_trees`) watches the cost.
- **Hub memory (P11)** is shared with other crates. The 03b harness measures its share and fails the bench if it exceeds the budget; the final number belongs to 16.
- **Fan-out amplification:** one outbox row becomes N subscriber sends. Each subscriber is bounded and lag-dropping, so the cost of a slow client is its own `Resync`, not the bus's time.
