### Verified facts that bind the tasks

- **F1 The hub serves `web/dist` itself** (`static_files.rs`, `Dockerfile`).
  - `index.html` is read once at start-up and the hub refuses to start unless it contains `__CSP_NONCE__`. The scaffold `index.html` has none. Every occurrence of the placeholder is replaced by that response's nonce.
  - `/assets/*` is `immutable` (hashed names, Vite's default). Everything else is `no-store`, including `public/` files, so fonts are imported from `src/` to land in `/assets/`.
  - Path segments are `[A-Za-z0-9._-]`, at most 128 characters; no symlinks; files up to 32 MiB; extension-less paths get `index.html`, a missing path with a dot is a 404. `.map` files are served as `application/json`. There is no `Content-Encoding`: the P10 gzip figure is measured, not served.
  - The image's web stage copies only `web/` and runs `pnpm install --frozen-lockfile && pnpm build` as root with `WORKDIR /src/web`. `pnpm build` therefore cannot read `../api` or `../design`: the generated API client and `tokens.css` are committed, the build-time gates read only `dist/`, and any write outside `web/` is best-effort.
- **F2 Production CSP** (`headers.rs`, `config.rs`): `default-src 'none'; script-src 'self' 'nonce-N'; style-src 'self' 'nonce-N'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'; object-src 'none'; require-trusted-types-for 'script'; trusted-types lanekeeper-docs lanekeeper-monaco`. The two names are the default of `LK_TRUSTED_TYPES`; no deploy file sets it; there is no `allow-duplicates`.
  - Consequences: no `blob:` or `data:` workers or fonts; no inline `style=""`. A `style` attribute that the HTML parser creates (`innerHTML`, `insertAdjacentHTML`, `setAttribute`) is blocked: `style-src` has no `unsafe-inline` and the policy has no `style-src-attr`, and a nonce does not cover an attribute. CSSOM writes (React `style` props, `el.style.x`) are allowed. Runtime `<style>` elements need the nonce. **Checked empirically in the installed Chromium 141** with a scratch page served with the exact `html_csp` string: a `style` attribute inserted through a Trusted Types `innerHTML` raised `style-src-attr` and did not apply; `el.style.top` applied; a `<style>` without a nonce raised `style-src-elem`, with a nonce it applied; a second policy name was refused (`TypeError` and a `trusted-types` report); a plain `innerHTML` string was refused. At most two Trusted Types policy names, each created once. No `eval`. `Worker()` takes a `TrustedScriptURL` here.
  - Static assets, and therefore worker scripts, carry the API CSP (`default-src 'none'`). `headers.rs` states that Monaco's needs "are recorded by prompt 08 in `design/DEVIATIONS.md`, never relaxed here".
- **F3 CSRF** (`csrf.rs`, `cookie.rs`). The layer wants exactly one `Origin` equal to the public origin, exactly one `X-CSRF-Token` header and exactly one `__Host-lk_csrf` cookie with the same value. The cookie is not HttpOnly, so the page reads it from `document.cookie`. A refusal is always the same 403 (`urn:lanekeeper:problem:csrf`).
  - A `<form method=post>` navigation sends `Origin: null` under `Referrer-Policy: no-referrer`, so every non-GET is a `fetch` (default mode `cors` sends the real Origin). Sign-out is `POST /auth/logout` by `fetch`. Sign-in is a GET navigation to `/auth/login?return_to=`.
  - The hub does not compose `CsrfLayer` yet (D109 D-2). The client sends the header regardless.
- **F4 SSE** (`sse.rs`, `source.rs`, `wire.rs`). Only the `Last-Event-ID` header is read. **A connection without it is `Fresh`: no replay and no `resync`**, and heartbeats carry no id, so a client that has seen no id-bearing event has nothing to resume from. Frames: `retry: 3000`, then replay or `resync`, then `id: N`, `event: <kind>`, `data: <json>`, and `: heartbeat` every 15 s. `resync` has no id. Limits: 5 streams per user (429 beyond), 30 minute maximum age, replay at most 1,000 events, oversize events stored as `resync`. Internal events never reach browsers.
- **F5 API responses are `no-store`** (only assets and blobs may be `immutable`), so the browser never revalidates them. "Requests use ETags" means the app's own fetch layer. Only six operations carry the `content` tag and an `ETag` (`openapi_conventions.rs`); `getGrid` has none.
- **F6 Problems.** `type` is `urn:lanekeeper:problem:<code>` on every problem and is the reliable discriminator. Only hub-platform and hub-writes problems also carry `code` (identity problems do not). Spellings mix kebab-case (`access-pending`) and snake_case (`token_expired`). `Conflict` (about a dozen operations) is typed with `current` required, though many 409s send no `current` (access-request decisions, admin rules, the duplicate PR). `LockedProblem` and `ConflictProblem` put `additionalProperties: false` in their extension branch, so a strict validator rejects the base fields of a real body (checked with jsonschema). `Problem.reason` is `RejectReason`, pinned to the domain enum by tests.

### T3: Live updates (P13)

- **Transport.** `sse-client.ts` is a `fetch` stream (`Accept: text/event-stream`, `Last-Event-ID` when known, `cache: 'no-store'`, same-origin credentials) read through `TextDecoder` with a WHATWG-rules line parser, a 64 KiB frame cap and a stall watchdog of 45 s without a byte. `EventSource` is rejected (no header control on a fresh object, no backoff control, no status codes). **One stream per tab:** the provider is mounted once at the router root, and `live/single-stream.test.tsx` counts open streams across navigation, React StrictMode double effects, reconnects and role changes; an e2e counts requests to `/api/v1/events`.
- **State machine.** `connecting`, `live`, `reconnecting` (attempt, retry time), `offline` after 3 consecutive failures (retry continues at the cap), with `dataAsOf` and `retryNow()`. Backoff 1, 2, 4, 8, 15 s with plus or minus 20% jitter; the server's `retry:` hint is the floor after a clean end. Offline shows "Live updates paused, retrying", disables writes with "Unavailable offline" (per-screen reasons from one table), keeps reads. 401 goes to sign-in (with the dirty-edit rule below), 403 stops and routes by problem type, 429 and 5xx back off, 400 stops with an error state.
- **Resume.** The last id is kept in memory from frames that have an `id`. **If the last id is null when the stream becomes live (first connect, or any reconnect with no id seen yet), the state is unknown (F4): the client refetches the active non-immutable queries once.** Otherwise a short blip relies on replay. After `offline`, and on any `resync`, it refetches the active non-immutable queries. A routine 30 minute rotation with an id never refetches. `live/sse-client.test.ts` has a rotation-with-no-id case.
- **Invalidation.** `invalidation.ts` is a pure `plan(event)` over the generated `DomainEvent` with an exhaustive `switch` and a `never` check; `apply()` coalesces over 100 ms, dedupes by key hash, falls back to "all active" above 200 distinct keys, and uses `refetchType: 'active'`. Lists follow the handoff's stable-view rule (`useStableList`): in-place updates when keys and order are unchanged, otherwise an "n updates" chip. `LiveIndicator`, the paused banner, `useStableList` and the toast hook are T3's (slice D); S0 mounts them.

## Cross-cutting designs

### How the CSP test gets the production policy

- `crates/hub/examples/web_fixture.rs` builds a `hub::Hub` with `Deps { static_files: Some(StaticFiles::open(web/dist)), .. }` and `HubSettings::from_lookup(env)` and serves `Hub::web` on loopback. The CSP header, nonce substitution, `trusted-types` list, `Cache-Control` and HSTS are the production code path (`security_headers`, `html_csp`, `StaticFiles`), not a copy. `LK_TRUSTED_TYPES` comes from the environment as in a deployment (default: the two names). The example sets `LK_IP_RATE_PER_SEC` and `LK_IP_BURST` high and `LK_TRUSTED_PROXY_HOPS=0` (the per-IP limiter, 50 per second with burst 200, would otherwise answer 429 to the asset sweep and Lighthouse), announces its port with a `std::io::Write` call (a scoped `allow` if it uses `println!`, because workspace clippy runs over examples with `-D warnings`), and uses no `unwrap`, `expect` or `panic`.
- `web/e2e/harness/serve.mjs` is a Node server on one origin: it proxies every non-API path to the fixture untouched (status, headers and body pass through) and answers `/api/v1/**` and `/auth/**` from the orval MSW handlers through `msw`'s `getResponse` and `sse` (both exported by `msw@3.0.1`), with scenario switching and raw-frame emission through a control endpoint. No service worker is used (registering one is governed by Trusted Types and the policy has no name to spare; the G0 spike confirms).
- `e2e/csp/csp.spec.ts` visits every route and opens every overlay (dialogs, alert dialogs, popovers, palette, menus, toasts, tooltips, and Monaco if W3 allows it) in light and dark. It records `securitypolicyviolation` events from an init script, console errors and page errors, **plus worker-scope console output (`page.on('worker')`) and a CDP Log and Audits listener**, and fails on any. It asserts the served header contains `require-trusted-types-for 'script'` and no `unsafe-` token, so a relaxed fixture cannot make the test vacuous. `assets.spec.ts` requests every file in `dist` (excluding `.map`) and expects 200 with the right type. `requests.spec.ts` fails on any request to another origin or to a path that is not a generated operation (this also backs "no AI chat"). The XSS corpus for `SanitisedDocHtml` runs here.

### Monaco under S12: an escalation (W3)

**Finding.** The prompt's stop rule applies: "Monaco can't run under Trusted Types and the CSP without unsafe exceptions". The evidence is static (F7); G0 measures it. Do not weaken the CSP in this plan. The first draft's mitigations (one policy, a nonce shim for `<style>`, features switched off) address the Trusted Types names and the `<style>` elements, and are still needed, but do not touch the inline `style` attributes that the core editor writes.

| Option | What changes | Cost and risk |
|---|---|---|
| (a) Allow style attributes: add `style-src-attr 'unsafe-inline'` to `html_csp` | `crates/hub/src/headers.rs`, its hub test, `docs/decisions.md`, a threat-model row; a 03b file, a separate PR; `script-src`, `style-src-elem` and Trusted Types stay as they are | An S12 relaxation that only a human can record; residual risk is CSS injection through an attribute, which needs an HTML-injection sink that Trusted Types already blocks |
| (b) Replace Monaco with CodeMirror 6 | D31 changes; handoff says "Monaco-style editor"; CM6 writes styles through CSSOM and supports a nonce | A different editor and a new dependency set; smaller bundle; some design deviations; a human decision on D31 |
| (c) Edit mode as a styled `<textarea>` with server validation | The prompt's "editing in Monaco" changes | No editor features (no tokens, folding, EOL status); trivially CSP-safe; lowest risk |
| (d) Read-only first: ship T4 without Edit mode | Edit mode, the editor part of T5 masking and the CRLF e2e move to a later task | Delays a headline feature |
| (e) Keep Monaco and keep the CSP: the `createHTML` hook rewrites `style="..."` into a data attribute and a `MutationObserver` applies it with CSSOM | Code only, in `src/editor/` | The mechanism works on a scratch page in the installed Chromium (no violation; the styles apply after one microtask, and a synchronous read right after insertion still sees unstyled boxes). Whether Monaco, which measures layout right after it inserts lines, tolerates that is the G0 question; high maintenance on every Monaco upgrade |

**Proposed default:** run G0, then ask the human to choose among (a) to (e); until then do not commit Monaco-shaped code. If (b) or (c) is chosen, T2's loader, the Monaco parts of T1 and the CSP overlay list change accordingly and the plan is amended. Whatever is chosen, the editor loads only in Edit mode.

**If an option with Monaco is chosen, the environment rules still hold:** one policy (`lanekeeper-monaco`) returned from `MonacoEnvironment.createTrustedTypesPolicy` for every name Monaco asks for, installed by `src/editor/environment.ts` before any Monaco module evaluates (an ES import hoisted above the assignment would make Monaco create its names directly); a `createHTML` pass-through (Monaco escapes model text) and a `createScriptURL` that accepts only same-origin `/assets/*.js`; no `default` policy; workers from `?worker&url` (never Vite's `?worker` wrapper, which passes a plain string, and never `?worker&inline`), wrapped by `createScriptURL`; a scoped `Document.prototype.createElement` shim that sets `.nonce` on `style` elements; features that need a worker or HTML off (links, word-based and quick suggestions, hover, occurrences, colour decorators), languages limited to the basic YAML, JSON, XML, properties and plain-text sets; the vendored DOMPurify must never run (a test asserts `sanitize` is not called, and zero `trusted-types` violation reports); **Unicode highlighting stays on for invisible and ambiguous characters if it works with the single editor worker** (S8); the global shortcut registry listens on `window` in the capture phase and the keymap tests run with the editor focused (Cmd+K, Cmd+B, Cmd+S, Esc), with the Cmd+K line-comment chord released through a Monaco command override.

### Masking and secrets in the browser

**The first draft stated as fact that read responses carry `[REDACTED: N chars, rule]`. They do not.** The contract masks only `EffectiveSetting` values and `ChangePreview`; `FileContent.text`, `DiffLine.text`, `SettingValue.text`, `TextHit.text`, `ServedFile.text`, proposal and draft hunks and `AuditEvent.diff` are raw ("exactly as written", and the domain says served text is not masked), carry no redaction flag or ranges, and `RevealRequest` requires a `SettingPath`, so a flagged value in a text file cannot be named. The client cannot mask what it cannot find (rule 7: only the engine scans). This conflicts with S14b ("the web UI masks flagged values by default"). **This is an AGENTS stop-and-escalate item (W5), and CG7 proposes the fix.** Until it is decided, the T5 masking test, the editor part of T5, and Edit mode for files that may hold flagged values are blocked, and T4 slices render text as received without claiming masking.

If CG7 is accepted, the client rules are: render masks from the server's `masks` ranges and the marker; never store a revealed value outside component state; `revealValue` is a mutation with `retry: false`, no Idempotency-Key reuse, `gcTime: 0`, reset on unmount; **auto re-mask after about 30 seconds and on `visibilitychange` to hidden or blur**; show the 429 wait (30 reveals per minute); no copy-to-clipboard of a revealed value; the editor makes masked regions read-only (or the server rejects a save that contains a marker, never writes it). `masking.dom.test.tsx` asserts on the DOM and on the query cache and mutation cache for every read operation, with fixtures from the 05 and 06 conformance suites (not hand-written MSW data), and a test that a failed reveal is never retried and the value is gone after the timer.

### Visual regression: references, tiers, dataset, baselines

- **References are rendered, not exported.** `e2e/visual/render-references.mjs` serves `design/handoff/screens` read-only from a throwaway static server and opens each frame in a sandboxed Playwright context with no CSP and none of the app's code. Reference and app are rendered by the same browser in the same run.

### Keyboard, accessibility, time and browsers

- **Keymap tests.** `extract-keymap.mjs` reads the `keys` table of the Engineering Handoff and expands it (`g then s / c / f / i / a`, `⌘1 … ⌘9`, `Space or x`, `↑ ↓`, `→ / ←`), `⌘` as `ControlOrMeta`. - **Accessibility gate.** `@axe-core/playwright` with tags `wcag2a`, `wcag2aa`, `wcag21aa`, `wcag22aa` and `best-practice` and **`target-size` explicitly enabled** (it is off by default), in light and dark over every tier-1 and tier-2 state, in real layout (jsdom `axe-core` is kept only for dialog structure). ## Risks

- **Monaco under Trusted Types and CSP (security, escalation).** The core editor writes inline style attributes that the policy blocks, and there are 11 or more policy names against 2. Contained by G0, the W3 options, and by committing nothing Monaco-shaped before the answer.
- **Masking (S14b).** Read responses are raw, so the web cannot mask. Contained by escalation W5 and by blocking the masking test and Edit mode for flagged files; the plan does not claim masking.
- **Contract gaps block slices.** CG1 to CG17 gate T3, parts of T4, T5 and T6. Contained by one early additive contract PR, defaults and recorded fallbacks, and `BLOCKED` rather than workarounds.
- **No handoff design for T6 and several surfaces.** The visual proof is app-owned for them. Contained by W6, the explicit label in every report, and the design owner's approval of every deviation.
- **Browser gates.** The browser is installed but is not the build Playwright 1.63.0 expects. Contained by `executablePath`, the recorded browser version, the CI build as the authority for baselines, and the option to pin 1.56.1 (W8).
- **Visual-regression fidelity.** References are rendered by an unmaintained runtime, with sample data the app must reproduce. Contained by the sandbox renderer, the dark-token assertion, the boards-based matrix, the parity dataset, tier 2, and the design owner's thresholds.
- **P10.** About 48 KB estimated headroom (the first draft's 65 was too optimistic), an uncompressed hub, a brittle 60 fps minimum, and Monaco's unknown size. Contained by the T1 shell-build checkpoint, the 225 KB warning, fetch-only warm-up, and escalation with measurements rather than loosening a budget.
- **Supply chain.** About 40 direct dependencies, a dev-only React 18, browsers and Lighthouse trees. Contained by exact pins at least 14 days old, `minimumReleaseAge`, blocked install scripts, `osv-scanner`, and the justification table.
- **Client-side secrets.** Tokens, reveal results, CSRF values must not reach caches, storage, URLs or logs. Contained by the secret-bearing mutation rules, no persister, no web storage outside `lib/prefs`, `no-console`, and the cache-scanning tests.
- **SSE limits and deploys.** Five streams per user means a sixth tab gets 429; a quiet client has no id to resume from; tabs outlive releases. Contained by backoff on 429, refetch when no id was seen, the stale-chunk handler and the single-stream test.
