# Design deviations

Record every intentional difference between the implemented UI and the Claude Design handoff here. The design owner approves each one.

| Screen / component | Deviation | Reason (security, performance or accessibility) | Approved by |
|---|---|---|---|
| Select | A styled native `<select>` (`NativeSelect`) for plain lists, and Popover plus Command for searchable ones, instead of Radix Select. | security: Radix Select renders a `<style>` through `innerHTML`, which Trusted Types and the nonce-only `style-src` refuse (S12). | pending |
| ScrollArea, scrollbars | Native overflow scrolling with a thin `scrollbar-width` and token colours, instead of Radix ScrollArea. | security: ScrollArea injects a `<style>` through `innerHTML` (S12). | pending |
| Icons | Inline `lucide-react` components, named imports, instead of `mask: url(assets/icons/*.svg)`. The 68 icons of the handoff are the only ones exported (a test checks both ways). | security and performance: no CSS-mask requests (about 80), icons colour with `currentColor`. The handoff's own CSP page recommends it. | pending |
| StatusBadge, pickup states | The handoff's `restart` variant ("Pending restart") is replaced by four pickup variants: Live, Live by HH:MM, Needs notify or restart, Needs config-server restart. The two that need action use the `restart` colours, the two that are live use the `sync` colours; icons `radio`, `clock`, `bell`, `server`. The handoff has no frame for any of them, so this is an interim design. | D85 (the handoff predates the pickup model), and no design exists (plan W6). Not one of security, performance or accessibility: see plan W36. | pending |
| Untrusted text (paths, names, values, diff lines, hits) | Bidi controls, zero-width, control and other invisible characters are shown as visible `<U+XXXX>` markers (`SafeText`), each with a name for assistive technology. The design shows such text as it is. | security: S8, a name can be made to read differently from what it is. | pending |
| Switch | The track is 28x16, as drawn in the Style Guide. The Engineering Handoff table says 28x14; the two pages disagree. | accessibility (the larger target) and handoff inconsistency (plan W25). | pending |
| Checkbox, radio | The visible box stays 14px as designed; the pointer target is grown to 24px around it with a pseudo-element. | accessibility: WCAG 2.2 target size (2.5.8). | pending |
| Truncated results banner | `TruncationBanner` says "Showing the first N ..." and never "shown of total", because the API reports only that the result was cut off. | contract: no total is available (plan CG16). Not one of security, performance or accessibility: see plan W36. | pending |
| Theme (light, dark, system) | The theme is a `lk_theme` cookie read by `/theme-init.js`, a classic script from the same origin, before the first paint, instead of the server writing `class="dark"` into the page. | security: the hub's CSP has no inline script (S12), and the hub has no per-user page. | pending |
| File editor (Monaco) | Monaco runs under the hub's CSP through one Trusted Types policy, a tag-aware rewrite of the style attributes it writes, and three narrow patches of built-ins (docs/threat-model.md, "The editor under the CSP"). Its hover, suggestions, parameter hints, links, code lens, inlay hints, colour picker, go-to-symbol peek and minimap are not in the app; the find widget, the context menu, go to line and the command palette are Monaco's own. | security: the contributions that render Markdown need a Trusted Types policy the hub does not allow and parse HTML with `DOMParser` (S12, plan W3 option (e)). | pending |
| Times | An absolute time is shown in UTC with the zone spelled out (`2026-10-17 06:42 UTC`); relative times ("4 min ago") are computed against a clock a test can freeze. The handoff's samples show times without a zone. | No design decision exists (plan W18). Not one of security, performance or accessibility: see plan W36. | pending |
| File viewer and diff (read-only) | Drawn by `CodeView` and `DiffView` over one virtualiser (rows of 18 px with a line-number gutter; the diff in split or unified mode, from hunks the server computed, with `n` and `p` between changes and folds over unchanged runs), not by Monaco. Monaco is loaded only by Edit mode; for an Editor and above its files are fetched while the browser is idle and never evaluated. If the editor chunk cannot be fetched, Edit mode shows `CodeView` with an inline alert. | performance: P10. Monaco is a few MB (about 1 MB gzipped) and evaluating it would cost the first screen; a 6,000-line diff must be interactive within 500 ms, and a virtualised view costs the same for 60 lines or 60,000. | pending |
| Long lists and the comparison grid, while scrolling fast | When the window of a virtualised list moves by eight rows or more in one frame, its rows are drawn as shells (the row's shape and nothing in it), and the content returns 120 ms after the scroll slows. A table with more than twelve columns draws only the columns in view, and keeps the first one in place. | performance: P10, 5,000 rows by 40 swimlanes at 60 frames per second. A cell that passes in under a frame cannot be read, and drawing every cell of every column gave 14 frames per second in the first measurement, before the columns were windowed and the fast-scroll rows made shells. | pending |
| A route whose files a deploy replaced | "A new version is available" with a Reload button: a banner while the page is up, the whole page when the route itself could not load. The page never reloads by itself, and Reload is held back, with the reason given, while a screen has unsaved work. The handoff has no frame for it. The router's `lazyRouteComponent` is not used: it reloads the page on a failed import and keeps its marker in `sessionStorage`. | performance and security: route-level code splitting is what keeps the first JavaScript under 250 KB (P10), and web storage is allowed only in `lib/prefs` (S10). An automatic reload would also throw away an unsaved edit. | pending |
