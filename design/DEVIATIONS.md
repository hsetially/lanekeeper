# Design deviations

Record every intentional difference between the implemented UI and the Claude Design handoff here. The design owner approves each one.

How to read it:

- **Screen / component:** the screen, grouped with the rows of the same screen. **Deviation:** what the app does and the design does not.
- **Reason:** the category the process allows is security, performance or accessibility (AGENTS.md, D71). Many rows here have another reason: the API does not carry the data the design draws (*contract*), the design draws a state with no frame or two frames that disagree (*handoff gap*, *handoff inconsistency*), or a later task builds it. Those say so, and say "Not one of security, performance or accessibility: see plan W36", because the design owner is asked to widen the list (plan W36) or to change the design.
- **Approved by:** `pending` until the design owner has approved the row, then the owner's name. An agent never writes anything but `pending`. `web/scripts/deviations.test.mjs` fails on a row with an empty cell or a screen named twice.
